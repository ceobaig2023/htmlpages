How the ecosystem fits together

These tools solve different parts of a Physical AI workflow; they are complementary, not interchangeable.

01 · Build the robot & world

OpenUSD + NVIDIA Omniverse / Isaac Sim

Import CAD/URDF/MJCF assets, assemble scenes, configure physics and sensors, render camera/LiDAR data, generate synthetic datasets and test robot software.

02 · Train robot behaviours

NVIDIA Isaac Lab

Define learning tasks, observations, actions, rewards and parallel environments. Train locomotion and manipulation policies using reinforcement learning or demonstrations.

03 · ROS-native simulation

Gazebo + ROS 2

Develop and test ROS 2 robot applications with simulated sensors, robot models, plugins, controllers, navigation and integration workflows.

04 · Deploy & validate

Real robot + edge compute

Connect sensors and actuators, run ROS 2 nodes and inference, measure latency and reliability, calibrate the system, then validate sim-to-real performance.

Key distinction: Isaac Sim is the high-fidelity simulation, scene, sensor and testing environment. Isaac Lab is the robot-learning framework for training policies at scale. Gazebo is a separate, widely used robotics simulator in ROS ecosystems. A digital twin is the connected virtual representation and workflow—not a single software package.

Projects that demonstrate job-ready ability

Project A · ROS 2 / Gazebo

Autonomous mobile robot

Build a differential-drive robot with LiDAR, odometry, mapping and Nav2 navigation. Demonstrate a goal-to-goal mission.

Evidence: GitHub repository, ROS graph, map, navigation video and test report.

Project B · Isaac Sim

Digital twin + synthetic perception data

Import a robot and environment, configure camera/depth/LiDAR sensors, vary lighting and object poses, export labelled data.

Evidence: USD scene, sensor configuration, dataset sample and evaluation metrics.

Project C · Isaac Lab

Learned manipulation or locomotion policy

Train a robot policy in simulation. Define observations, actions, rewards, training curves and robustness tests.

Evidence: training config, checkpoints, learning curves and repeatable evaluation.

Project D · Physical AI

Language-guided robot task

Prototype a system that interprets a constrained instruction, identifies an object, plans a safe action and executes it in simulation.

Evidence: architecture diagram, task success rate, failure analysis and demo.
